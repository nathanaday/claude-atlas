# Knowledge base clusters: implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A knowledge base may list other knowledge bases as members. A project mounts that cluster and reaches every member, and a member added later reaches every project at the next refresh.

**Architecture:** The cluster is a knowledge base with a `members` list in its identity file. `registry.Scan` resolves the members, then expands a project's cluster mount into one derived mount per member, tagged with the cluster it came through. Everything that already walks `Entry.Mounts` — symlink maintenance, lint, the tools, the hook, the view — sees the members without knowing clusters exist.

**Tech Stack:** Go 1.24, Bubble Tea, Lip Gloss. No new dependencies.

**Spec:** `docs/superpowers/specs/2026-09-16-knowledge-base-clusters-design.md`

## Global Constraints

- Dependencies stay as they are: `gopkg.in/yaml.v3`, the MCP `go-sdk` v1.4.0, Bubble Tea, Bubbles, Lip Gloss. Do not import an indirect module directly.
- A vault's own facts change only through `vault.UpdateConfig`, which validates the whole identity file against the kind and commits it as a `setup` operation. Nothing else writes an identity file.
- The scan is the truth. Every command that acts on a vault scans afresh; `state/registry.json` is for display only. A cluster is never recorded in the atlas config.
- A knowledge base never learns who mounts it, and a member never learns which clusters hold it. Both lists are computed from the other side's identity files.
- `kb/` symlinks are local state that git ignores. `mount`, `refresh`, and `doctor` create them; nothing else needs to.
- TUI models keep all logic in `Update`; tests drive them with `tea.KeyMsg` and read `View()`. Lip Gloss renders plain text under `go test`, so tests compare plain strings and assert colors only through style getters.
- The view's frame is exactly the screen's height and no line reaches the screen's width. A new line in the view is capped the way its neighbours are.
- Prose in comments and docs follows the writing guide: short plain sentences, one idea each, active voice, no metaphors, and never the words flag, genuine, honest, shape, load bearing, judgement call, earned its keep, worth flagging. Comments are lean; the code is the source of truth.
- Commits: `git -c user.name=nathanaday -c user.email=nraday1221@gmail.com commit`, no `Co-Authored-By`, subject `area: what changed`, stage files by name, never stage `.superpowers/` or `.worktrees/`.
- Before every commit: `gofmt -l ./internal` prints nothing, `go vet ./...` and `go test ./...` pass.

```go
// expand is the mounts a project reaches through the clusters it mounts, one per member,
// resolved the way a recorded mount is. A member the project already mounts itself is
// left out: the project asked for that knowledge base by name, so its own mount stands.
func expand(project *Entry, byID map[string]*Entry) []Mount {
	taken := map[string]bool{}  // mount names in use, lowercased
	mounted := map[string]bool{} // knowledge base ids the project reaches already
	for _, m := range project.Mounts {
		taken[strings.ToLower(m.Name)] = true
		mounted[m.ID] = true
	}
	var out []Mount
	for _, m := range project.Mounts {
		cluster, ok := byID[m.ID]
		if !ok || len(cluster.Members) == 0 {
			continue
		}
		for _, ref := range cluster.Members {
			if ref.Error != "" || mounted[ref.ID] {
				continue
			}
			kb, ok := byID[ref.ID]
			if !ok || kb.Kind != vault.Knowledge {
				continue
			}
			mounted[ref.ID] = true
			name := memberName(kb, cluster, taken)
			taken[strings.ToLower(name)] = true
			member := Mount{
				ID: kb.ID, Name: name, Access: m.Access, Through: cluster.Name,
				Path: kb.Wiki(), Effective: Effective(m.Access, GrantedAccess(*kb, project.ID)),
			}
			out = append(out, member)
			kb.MountedBy = append(kb.MountedBy, Ref{ID: project.ID, Name: project.Name, Access: member.Effective})
		}
	}
	return out
}

// memberName is the folder a member takes under kb/: its own name, the cluster's name and
// its own when that is taken, and its id's first eight characters when that is taken too.
func memberName(kb, cluster *Entry, taken map[string]bool) string {
	for _, try := range []string{kb.Name, cluster.Name + "-" + kb.Name} {
		if name := links.CleanName(try); name != "" && !taken[strings.ToLower(name)] {
			return name
		}
	}
	return links.CleanName(cluster.Name + "-" + kb.ID[:min(8, len(kb.ID))])
}
```

Notes for the implementer:
- `registry` already imports `links`; `links.CleanName` is what `vaults.Mount` uses to name a mount folder, so a member's folder is named the same way.
- The expansion runs after the recorded mounts resolved, so `m.Access` is what the project asked the cluster for, and a cluster whose own id the scan did not find is skipped by the `byID` lookup.
- A cluster that is a member of a cluster cannot be written by `vaults.AddMember` (Task 3). If a hand-edited file holds one, `expand` adds that member's own mount but does not recurse, so nothing loops.

```go
package vaults

import (
	"fmt"
	"strings"
	"time"

	"github.com/nathanaday/claude-atlas/internal/registry"
	"github.com/nathanaday/claude-atlas/internal/vault"
)

// IsCluster reports whether a knowledge base gathers others. A knowledge base with no
// members is an ordinary one; gaining a member makes it a cluster and losing its last
// makes it ordinary again.
func IsCluster(e registry.Entry) bool { return e.Kind == vault.Knowledge && len(e.Members) > 0 }

// AddMember records kb in cluster's identity file. A project that mounts the cluster
// reaches the new member at its next refresh. It refuses a member that is not a knowledge
// base, a cluster as a member, and a knowledge base the cluster already holds.
func AddMember(cluster, kb registry.Entry, now time.Time) error {
	if cluster.Kind != vault.Knowledge {
		return fmt.Errorf("%s is not a knowledge base", cluster.Name)
	}
	if kb.Kind != vault.Knowledge {
		return fmt.Errorf("%s is not a knowledge base", kb.Name)
	}
	if kb.ID == cluster.ID {
		return fmt.Errorf("%s cannot be its own member", cluster.Name)
	}
	if IsCluster(kb) {
		return fmt.Errorf("%s is a cluster; a cluster does not hold another cluster yet", kb.Name)
	}
	for _, m := range cluster.Members {
		if m.ID == kb.ID {
			return fmt.Errorf("%s already holds %s", cluster.Name, kb.Name)
		}
	}
	return vault.UpdateConfig(cluster.Path, "member "+kb.Name, now, func(c *vault.Config) error {
		for _, m := range c.Members {
			if m.ID == kb.ID {
				return fmt.Errorf("%s already holds %s", cluster.Name, kb.Name)
			}
		}
		c.Members = append(c.Members, vault.Member{ID: kb.ID, Name: kb.Name})
		return nil
	})
}

// RemoveMember drops the member named by its id or its name from cluster's identity file.
// The knowledge base is untouched, and a project that mounts the cluster loses the mount
// at its next refresh.
func RemoveMember(cluster registry.Entry, target string, now time.Time) error {
	if cluster.Kind != vault.Knowledge {
		return fmt.Errorf("%s is not a knowledge base", cluster.Name)
	}
	return vault.UpdateConfig(cluster.Path, "drop member "+target, now, func(c *vault.Config) error {
		var keep []vault.Member
		removed := false
		for _, m := range c.Members {
			if m.ID == target || strings.EqualFold(m.Name, target) {
				removed = true
				continue
			}
			keep = append(keep, m)
		}
		if !removed {
			return fmt.Errorf("%s holds no member named %q", cluster.Name, target)
		}
		c.Members = keep
		return nil
	})
}
```
